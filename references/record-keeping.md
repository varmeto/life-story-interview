# 归档与续聊规则

在首次归档、变更确认状态、更正、删除或恢复访谈时读取。本规则控制本 Skill 自己生成的记录，不改变宿主的权限和存储政策。

## 保存条件与位置

开始访谈不自动等于允许写文件。“把这次记录保存下来”等明确表达可作为保存授权；已授权同一记录目录后，不为每次追加重复索取批准。

1. 用户指定位置时使用该位置，先确认目录确实可写、属于用户授权范围。
2. 有保存授权、但未指定位置时，默认候选为用户当前可写工作区下的 `interview-records/<session-id>/`。`session-id` 使用宿主可核实的日期加简短主题，例如 `2026-01-15-reading-group`；重名时加短序号，不覆盖旧记录。
3. 当前工作区不明、只读、属于公开分发仓库或 Skill 安装目录时，先保持聊天副本，只询问一次合适的保存位置，不擅自切换到其他磁盘、云盘或个人资料库。
4. 不将记录放进 Skill 本体或将其设为全局指令；不自动发布、上传、同步或 Git 提交。用户明确选择外部存储时，按该平台授权处理，并说明实际存储位置。
5. 用户未授权、文件能力缺失、写入失败或被拒绝时，明确说明没有成功保存，提供可复制副本。未经授权不尝试绕过或换路径写入。

本地归档使用三个 Markdown 文件，不要求数据库或专用记忆服务：

```text
interview-records/<session-id>/
├── transcript.md    原始问答
├── notes.md         结构化记录与确认状态
└── checkpoint.md    续聊检查点
```

目录仅表示默认本地组织方式，不保证硬盘加密或访问权限已配置。不要把“本地保存”说成已获得额外安全保护。

## 原始问答

- 按对话顺序给采访者问题和讲述者回答分配稳定定位，如 `Q01`、`A01`；没有新问题的主动补充也单独编号，并注明“主动补充”。
- 采访者的回应、阶段回顾和收尾也保留在原始顺序中，可使用 `R01` 等定位，避免只留问题而丢失语境。
- 保留完整回答，包括细节、自我修正、重复、含混和“记不清”。记录来自已经收到的文字或转写，不声称保留了未获得的录音、停顿或语气。
- 只整理明显错字、标点和断句；姓名、数字及含混词不得猜改。只有用户明确纠正后才采用更正，并记录更正来源。
- 长回答或长会话可按段落、日期或阶段拆分，必须保留连续定位与后续文件链接。不要为减少文件长度而以摘要替换原文。
- 普通更正保留原话和校正记录，表示“后来更正为”，不暗中改写历史回答。明确删除或不记录的要求优先于此保真规则。

## 结构化记录

每条有稳定编号和原文来源，例如：

`F03｜本人确认的自述｜约2019年开始参与读书会；时间记忆不确定｜A02、A04；确认依据：A07`

使用三种可并存的信息标记：

| 标记 | 意义 | 更新条件 |
| --- | --- | --- |
| 本人确认的自述 | 讲述者明确确认记录准确表达自己的说法 | 对应的明确确认，不能从沉默或继续聊天推断 |
| 待确认 | 已讲过，但尚未明确确认记录 | 等待本人后续核对；不阻止继续访谈 |
| 记不清或存在冲突 | 本人不确定，或多个说法尚不能协调 | 保留原有精度与并列说法，不自行补全 |

“本人确认的自述”可以仍附“年份不确定”等标记：确认的是记录忠实，不是把近似时间变成精确日期。

- 主题访谈按话题整理；编年史按已知日期、年龄或阶段组织，无法排序的放入“时间待定”，不推算未经确认的出生年份或年龄。
- 事情经过、感受、本人解释分开。只记录“讲述者说／认为”，不升级成对第三人的事实判断，不添加心理画像。
- 记录确认范围与依据；“第一条对”只更新第一条，“第二条改成……”只修正第二条，不能把其他条目顺带确认。
- 一段收尾时只回顾需要确认的新增或更正内容，不每次重发整份档案。不将未确认记录当作后续提问的既定前提。
- 用户纠正可改正文的当前说法，但保留原文定位和校正依据。旧说法标为“已更正”，不得继续并列为当前事实。
- 出现凭据、验证码或账户密钥时，不把它们整理进个人档案；需要确认的姓名或生活经历不能因此一概被剔除。日常经历在本人授权范围内记录，不要求为了归档补充敏感信息。

## 不记录与删除

- 尚未写入时直接排除指定内容；归档可用中性占位注明“按讲述者要求未归档”，不保留该段细节。
- 已写入时，按用户明确范围查找本 Skill 可控制的原文、结构化记录、检查点及其他派生副本；依宿主权限处理。完成后说明处理范围，无法访问或无权删除的部分如实说明。
- 不在校正日志或检查点中重新抄回被要求删除的内容；只保留处理事实及受影响的编号，除非用户也不希望留该痕迹。
- 不声称删除了平台会话、系统日志、模型记忆或不可控制的备份。不要为删除归档而擅自操作其他应用或整个工作区。

## 检查点与恢复

记录用户选择的主题／模式、已讲事件、确认状态、原文最新编号、跳过话题，以及当前保存位置或“仅在聊天中”。可选续聊入口不是待完成任务，不设提醒或自动跟进。

收到“继续上次”时：

1. 只读取该用户授权且实际可访问的检查点和对应记录，不扫描整台电脑或外部记忆服务。
2. 用一句话说明上次讲到哪里；用户已给新方向时直接跟随新方向，不先要求补完旧计划。
3. 没有新方向时，最多给一个温和的续聊问题。不要重复已答的问题，也不要主动重开跳过话题。
4. 检查点缺失或不完整时，说明缺少哪部分，请用户提供简短定位或记录副本；不伪造上次内容。

## 无文件能力时

在自然收尾或用户要求时，按模板输出“原始问答”“结构化记录”“续聊检查点”三部分。内容长则分段提供，保留全部原文，不以摘要代替。明确标注“仅在本次聊天中提供，未写入文件”；用户下次可以附上这些材料续聊。
